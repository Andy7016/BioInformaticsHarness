# 把资源缺口纳入研究闭环

## 当前实施选择

闭环作为 Harness 内部按需启动的研究调控层，调用具体任务、方法指南和执行工具。[D52](../../core/docs/design/29-evidence-gap-control.md)说明层次、接口与取舍，[操作指南](../../core/docs/methods/guides/resource-gap-loop.md)说明怎样从资源观察回到主张决定。本文保留初始规划中的条件与理由。

## 何时补充资源

当数据、实体关系或注释的缺口会改变当前主张、评价单位或实际用途时，触发资源补充。例如，研究要讨论未见基因或家族外泛化时，按短序列相似度或名称分组未必能支撑该评价单位；若问题仍局限于固定窗口的档案预测，补基因映射未必改变研究判断。先说明缺口会影响哪项结论，再决定是否获取资源。

## 研究自检查流程

闭环顺序：**发现缺口 → 说明补充价值与预算 → 选择来源并获取 → 核对实体、版本、覆盖与冲突 → 接入划分或评价 → 判断结论是否改变 → 更新方案、限域或停止。** 本规划将这种研究过程中的自监督称为“研究自检查与资源补齐”，关注证据怎样支撑研究单位和下一步选择。

理论层判断映射是否会改变研究问题或证据强度；应用层选定实体定义、来源、使用位置、验收方式和停止条件；执行层获取映射、保留来源版本，并报告覆盖、歧义与冲突。三层都要说明选择理由。可接受的来源应能说明维护者、版本、实体命名空间、许可和覆盖范围；预算由该研究预先限定。

## 映射怎样进入科学评价

基因、转录本、蛋白、家族和结构域是不同实体。一个基因可对应多个转录本或蛋白，映射也可能多对多；应保留这些关系并按问题定义家族粒度。未知映射记为未知，不作为阴性标签。精确序列或名称形成的组仍是代理组，不改称基因独立。覆盖或冲突达到什么程度才可使用，要在查看模型结果前按用途确定；没有适用于所有研究的统一门槛。

每条配对或分组关系都应连到来源版本、映射记录和实际消费它的代码位置。选择适合当前问题的参照，记录映射是否改变分组、样本归属、评价数值及结论。只获得部分映射时，还要检查留下的样本与原样本有何不同。若可靠映射不可得，可继续使用清楚标注的代理单位并收窄主张；若代理单位无法回答目标问题，则暂停或更换问题。

## 从论文提取控制经验

从论文、补充材料、评审意见和作者回复提取经验时，按“动机与条件—所选方法及替代—信息用途—操作—结果—继续、回退或改判”记录。作者明示的决策与本项目据材料重建的控制规则分开保留；后者作为待检验方案。论文报告与本地实际执行分别标注；评审意见可指出缺口，但不能单独证明作者曾采取未报告的探索。多个案例反复支持的做法才形成共同指导，任务特有做法保留触发条件。先在模型研究专题中积累，再考虑扩展到更广的方法论。

## 试点安排

Yeast 同一课题的补研究已完成本轮封存首交。Splice 已实际读取官方资料，检查其是否足以定义基因／家族评价单位；本轮选择保留较窄的档案分类问题。取得适当的实体关系后，再制定新的科学评价方案。计划细节见[资源闭环计划](../../machine/future-plans/resource-completion.json)；现有方法入口包括[领域验证指南](../../core/docs/design/21-domain-validation-guidance.md)与[序列新颖性指南](../../core/docs/methods/guides/sequence-novelty-and-background.md)。
