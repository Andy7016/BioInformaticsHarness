# 文档约定

## 写给使用者

README 先说明项目的用途，接着给出安装方式和最短可用例，再链接到详细文档、示例、贡献方式和许可证。

方法指南按研究者做事的顺序展开：研究对象与问题、适用条件、方法选择、操作步骤、结果解释和下一步。给出选择理由和合理替代，让读者知道怎样作判断。

写明已观察到的结果和会影响使用的条件。首次提出推断或设想时说明依据；一段文字围绕一个问题，使用具体动作和常用词。图表用于解释关系，标题用于帮助查找。

## 写给工具和 agent

版本身份、环境、运行状态、检查记录、证据范围和原始技术说明存为结构化文件。新的记录优先使用 JSON；逐项维护的来源和过程记录使用 JSONL。

这些资料放在 [machine](../machine/) 目录。文件索引可以同时出现在两类文档中，人读文档使用清楚的链接名称，技术记录保留精确字段。

## 维护方式

- 改动先说明解决的问题与理由，历史版本和原始研究材料继续保留。
- 方法或结果有变化时，更新相关指南、来源索引和版本记录。
- 人读说明和机器记录使用相同的主题或文件路径，方便相互查找。
- 法律文本、程序夹具和历史研究记录按各自用途维护。

写作参考来自较早的 CPython、NumPy 和 scikit-learn 项目说明，见[来源与设计索引](REFERENCES-AND-DESIGN.md)。操作细则见[agent 文档](../machine/AGENT-INSTRUCTIONS.md)。
