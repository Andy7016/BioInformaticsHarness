# 在进行中的课题里更新 Harness

更新 Harness 的目的是让新指导帮助课题继续推进。先保留当前研究的来路，再判断哪些变化需要进入现有分析、下一轮计划或后续交付。

## 先确定正在使用的版本

每次分发都附上来源记录与文件清单。来源记录写明上游仓库、所基于的提交、工作区是否还有修改，以及本次交付包的独立身份。接收者从这份记录确认版本，再检查收到的文件。

正式分发宜先提交，再固定交付包；开发中的工作快照也可以用于明确范围的试用，记录其基于的提交与额外修改。旧包没有提交记录时，保留“提交未知”，用其原有清单建立可比较的旧版本。

课题每轮交付记录实际采用的包、作用范围和采用时间。收到文件、读过指导、采用指导分别记录；某个子任务继续使用旧版时，写清它的版本与下一次复议点。

## 维护能指导重读的变化索引

[版本记录](../CHANGELOG.md)为使用者说明更新解决了什么问题，并链接到相应的[结构化变化索引](../machine/changes/)。重要的框架、方法卡和工具接口变化，在索引中列出：

- 改动的文件、需要一起重读的材料与章节；
- 适用条件，以及应回看哪些研究判断、计划或交付；
- 预期的适配动作和接受条件。

每次有意义的提交携带对应索引。索引文件采用追加方式维护，纠正旧指导时新增替代说明，保留旧条目供历史回溯。交付工具从 Git 历史取得索引首次进入仓库的提交；追补历史说明时另记其覆盖范围。

重要文件有变化却没有索引时，更新计划仍把它列为待裁定项。agent 要先说明变动的用途，再判断与课题的关系。

## 保留进度，逐项适配

1. 固定旧包及当前进度入口：研究问题、已作决定、证据与阅读账本、计划、运行记录、模型状态、首次结论和修订记录。保护清单标明本轮需要保持原样的材料。
2. 比较旧包与新包，生成变化和重读清单。先读变化索引，再按其指向重读完整的相关指南或方法卡，并联系当前课题。
3. 对每项变化选择：保留现有判断、修订、补充适用条件、明确不适用，或延期裁定。说明对当前交付与下一验收点分别有什么影响。
4. 需要修订时，新建派生研究记录，并连接受影响的旧判断、具体修订、证据和接受意见。涉及科学内容的改判交给现有 [revisor 流程](../core/docs/methods/guides/revision-responses-and-acceptance.md)确认。
5. 写下新版本在何种范围内生效、由谁接受、下一个动作与责任人。未完成的影响项保留待裁定状态，相关交付沿旧版范围记录，待影响明确后再作接受决定。

例如，新的工程方法卡提醒区分预训练、任务训练、适配和预测，接收课题可重新标注已有流程，检查实际进入模型的对象与运行证据。旧模型和既有预测结果继续保留；需要补分析或重跑的部分，另立有理由的任务。

旧结论继续使用形成时的版本和标准。新的复议可以补充或改变结论，并同时保留原判断与改判理由。接口有变化时，优先生成格式适配记录，把旧科学结果和新格式连接起来。

## 实际使用

[更新工具](../tools/guidance_update.py)提供来源快照、接收检查、差异计划和采用记录检查。命令与字段见[机器契约](../machine/guidance-update-contract.json)，契约还提供一项采用决定的填写模板。

工具检查材料身份、必读回执、保护文件和派生记录之间的连接；研究者与 revisor 负责内容理解、适用性和科学判断。工具完成检查后，由课题的责任人确认生效范围，再把新版本写入后续任务。

## 用 Git 支持课题分流与反馈

建议保留两层仓库关系：公共 Harness 维护指导和工具，各研究课题维护自己的证据、决定与运行历史，并固定所用 Harness 版本。可通过版本化目录或独立克隆接入；需要把依赖固定到提交时，可选用 [submodule](https://git-scm.com/docs/git-submodule)。

研究课题各自形成可追溯的演进路线。提炼出可复用改进后，再从 Harness 上游建立反馈分支，提交最小问题、适用条件、拟议规则、正反例和验证结果。上游审阅提炼后的改动，课题原始材料继续按原有归属保存。

迁移历史时可用 [Git bundle](https://git-scm.com/docs/git-bundle)传递选定的提交与引用；未提交的工作文件需要单独打包。[Codex worktree](https://developers.openai.com/codex/app/worktrees)适合同一仓库内的并行工作，它共享 Git 历史，仍需为交付记录明确版本与责任。

长期运行时，在恢复、接收更新和阶段交付三个节点复查当前版本与采用范围；每轮无需重读全部 Harness，优先处理差异索引、影响项与待裁定项。

## 更新运行与时间政策

接收运行策略更新时，同时检查调用方是否依赖旧默认值。为新的长程任务选择进度检查点和有依据的执行预算，保留旧实验的原窗口、结果与投入。中断后的恢复另记来源和预算，沿[续跑指南](../core/docs/methods/guides/task-continuity.md#时间预算与恢复)连接当前责任与下一验收点。

## 保留课题的方法经验

方法卡更新时，将[本地经验](../core/docs/methods/guides/method-experience.md)的来源版本与新指导对照，复议哪些条件仍适用、哪些下一动作需要改变。保留原经验，新写复议结果。课题经验随原研究保存；提炼为上游候选时，附适用条件、证据与反例，再按内容和可分享范围审阅。
