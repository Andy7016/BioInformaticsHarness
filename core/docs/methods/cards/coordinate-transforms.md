# 坐标与参考系变换

## 适用条件

当研究把一个坐标系统、索引系统或几何参考系中的对象转换到另一个系统时启用。本卡覆盖 assembly/strand/crop/bin/TSS/track 的联合映射、序列—残基—原子映射、RNA 二级结构索引，以及自由构象与固定口袋 pose 的参考系关系。只有保留原坐标身份、变换步骤和边界语义，才能把“坐标对应”写成可追溯关系；没有这类变换时记 `not-applicable`。

本卡不规定唯一的组装版本、窗口、bin 大小、原子集合、对齐算法或几何不变量。具体算法可由版本化的外部方法承担，但适用对象和输入输出身份必须绑定。

## 最少必要材料

- `source_ref` 与 `target_ref`：对象/文件/assembly/model/chain/track 的稳定 ID、版本、坐标单位、索引约定（例如 0-based 半开区间或 1-based 闭区间）、方向和参考原点。
- 变换链：每一步的名称、输入/输出身份、参数和顺序。基因组序列按实际参与映射的对象记录 assembly、strand、input crop、output bin、TSS 或 track 之间的关系；普通基因组区间不虚构未参与的 TSS/track。结构任务记录实际参与的序列/残基/原子集合与对齐对象；只有涉及 pose/pocket 时，才记录相应的共同或相对参考系。
- 边界与信息损失：crop 外区间、尾段、部分 bin、缺失残基/原子、反向互补、padding、mask、非整数或非一一映射如何处理；被丢弃的信息和有效分母另列。
- 可逆性：记录是否能逆映射、逆映射需要哪些 sidecar；若变换不可逆，明确下游允许保留的聚合主张，不能把一个目标 bin 伪装成唯一的碱基位置。
- 期望与观察：若变换由组件执行，记录预期的坐标身份和实际产物/回执；参数存在本身不等于变换已经发生，见[执行证据与实际消费](execution-evidence.md)。

## 可判断的检查

1. 用小区间往返检查 ID、方向、原点和边界。对 assembly/strand/crop/bin/TSS/track，至少应能说明一个输入区间如何进入输出 bin，尾段或 crop 外部分是否被保留、聚合或排除。
2. 对序列—残基—原子映射检查主键和集合守恒；重编号、插入码、链交换、缺失原子或 altloc 不得静默变成另一个对象。
3. 对自由构象与固定口袋 pose，分别记录要保持的对象关系。刚体变换可以改变绝对坐标而保持适当的内部距离；固定口袋评价还必须说明 ligand 与 pocket 的共同或相对参考系。不要把自由构象的内部不变量自动套到口袋相对位置。
4. 若声明了逆映射，检查每个目标对象是否有唯一或有明确多值的来源；若变换不可逆，检查报告是否标出 `unknown`/聚合边界，而不是生成虚假的精确来源。
5. 证据不足时区分 `unknown` 与 `fail`：身份、单位或必要边界缺失属于 `unknown`；已记录的目标身份与实际产物矛盾、或越界后仍声称完整覆盖属于 `fail`。

## 合法替代与不适用

不同 assembly、strand 方向、crop、bin 大小、TSS 定义、track 分辨率、原子集合和对齐算法都可以使用，前提是把对应变换链和局限写清。对于不可逆聚合，可以合法地只作 bin/轨道层主张，或另存逐碱基/逐原子证据。对于 pose，可使用任务合适的刚体对齐、共同参考系或显式相对坐标；不强制某一种 RMSD、不变量或匹配算法。没有坐标转换时跳过本卡，不要求虚构几何步骤。

## 小型验收例

- 正常：assembly 区间 `[100,108)` 裁到以 96 为原点的 crop，并按 4 个碱基一 bin；记录相对区间 `[4,12)`、输出 bin `[1,3)`、方向和 TSS/track 身份。若另一个 track 以 1-based 闭区间表示，转换后的边界也单独记录。
- 失败：长度为 16 的 crop-local 区间中，正向 `[2,6)` 反向应映射为 `[10,14)`；若把反向局部区间仍写成 `[2,6)`，或把 crop 外的尾段静默补成有效碱基，应拒绝该记录。正链和反链共享同一 assembly 的全局参考坐标本身可以合法，不因坐标数值相同自动失败。
- 正常：把自由配体整体平移或旋转后，任务声明的内部距离仍作为几何见证；固定 pocket pose 同时保存 pocket 参考系和 ligand-pocket 相对量。这个例子展示如何选见证，不规定所有结构任务必须保持同一数值。
- 失败：4 个碱基聚合为一个 bin 后声称能唯一逆推出某一个碱基；应标记不可逆，并限制主张到 bin/轨道层，或补充逐碱基记录。
