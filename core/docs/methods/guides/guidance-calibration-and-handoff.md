# 从评审请求到可交接任务：校准与执行指南

版本：2026-10-18。适用于收到具体评审请求后组织回应，或对已有案例复盘。依据：[公开研究设计与方法索引](../../../../docs/REFERENCES-AND-DESIGN.md)。配合[路线指南](revision-responses-and-acceptance.md)、[测量到主张](measurement-to-claim.md)和[交接契约](../revision-guidance-contract.md)使用。

## 先说明正在判断什么

先记录原请求ID、来源版本与定位，再用一句话说明“这项请求需要改变哪一个对象或判断”。例如“说明计算知识特征在预训练中做什么”，与“验证该特征能提高新靶点活性预测”需要不同工作。保留原请求的必需/可选及AND/OR关系，不把解释成功当成后者的验证。

本次评价键为 `request × required_scope × route × guidance_version`。旧案例分数原样保存；新口径在独立复盘层评定。只评价所选解释路线时，写 `scope_relation=selected_route_only`，并把原科学问题中尚未回应的部分写进unresolved。

## 共同评分锚点

G回答的是“该版本指南给执行者多少可用方法”。先从源文支持的研究选择重建任务，再对照以下五维；不要先按量表拼出一段像指南的文字。

| 维度 | 要找的具体支持 | 不够的写法 |
| --- | --- | --- |
| procedure | 应按什么顺序处理对象、作哪些判断或选择 | 仅说“重视生物意义” |
| input_use | 需要哪些资料，各自用于哪一步，缺失怎样处理 | 仅列“数据、模型、代码” |
| next_action | 执行者拿到材料后第一个可做动作是什么 | 仅说“进一步研究” |
| output | 可交付的文本、表、规格或小工件是什么 | 仅说“形成报告” |
| acceptance | 谁按什么谓词、例子或反例接受、否定或保留未知 | 仅说“保证正确” |

| G分类 | 使用锚点 |
| --- | --- |
| exact | 适用五维均有该版本指南的具体支持，足以开展所评义务；必要领域参数可据来源实例化，关键方法和判断依据已有支持。 |
| partial | 至少有可采用的操作支持，但关键步骤、输入转换或判据仍需另行设计。明确指出缺哪一维、怎样补。 |
| topic_only | 主题/责任相邻，尚没有可采用操作。不能只因没有实际训练就归到这里。 |
| absent | 已读范围内没有对应支持。保留读取范围，不把“未读”当缺失。 |
| unknown | 必要指南版本、材料或语境未取得，暂时不能判断。 |
| not_applicable | 所评义务不在适用范围内，给出理由。不是通过，也不填补分母。 |

exact须指向指南版本、章节/行或JSON指针。partial不得折算0.5。新补的领域步骤、作者已经完成的实验和当前任务的执行证据分别记录，不能回填为冻结指南能力。程序只能发现声明矛盾和证据缺口；五维覆盖是否真实仍由阅读者判断。

本视图的absent用于说明所读指南没有支持，不自动覆盖历史协议中的unmapped/new_candidate；历史NA与本视图not_applicable保留原始拼写及适用性理由。全部维度均不适用时不能以exact通过。

E记录能否表达/追溯；V逐项展示“可判断的谓词—具体实现或人工规程—实际检查结果”。记录齐全不是科学问题已解决。比较只在相同义务、范围、版本和评价路线下进行；本轮复盘不合并异质271行计算提升率。

## 交给执行者之前的六步

1. **保留请求。** 写原请求和定位、观测/推断层、版本关系；代理稿和正式稿不冒充精确送审稿。
2. **选定回应路线。** 写解释、补分析、验证、限域或反驳的理由，明确当前owner与未决问题。历史作者路线另列。
3. **列必要输入及用途。** 每个文件单独列来源和版本；每个使用位置写明材料定位、用途及是否为当前路线所需。缺少原始实验只影响依赖该实验的路线。
4. **分派最小任务。** 路线owner派发给具名执行者，写下一动作、输入、产物和停止条件。可共用来源文件，不复制整个聊天。
5. **先写验收。** 为关键产物列正常、明确错误和材料缺失的出口。把检查代码或人工规程的身份、能力范围与本次回执分别落地。
6. **再接收产物。** 核对版本和文件身份，按范围检查内容，记录残余问题。若要求范围改变，回到选择记录，不静默扩大任务。

## 一张足够接手的任务单

| 项目 | 要交代的内容 |
| --- | --- |
| 原请求与当前范围 | request_id、原文定位、required_scope；full_request还是selected_route_only |
| 路线与负责人 | current_work/historical_author、选择理由、owner；任务执行者owner与assigned_by |
| 最小输入 | 每个文件单独记录来源、版本、具体定位、用途及是否为当前路线所需 |
| 下一动作 | 例如先抄出“计算特征→模型目标→评价事件”，再写受限解释；不补未读实现 |
| 预期产物 | 具体解释段、字段表或可计算小文件，保留新写文本的身份 |
| 验收与出口 | 输入/实现出处、谓词、检查人、回执；缺源unknown，明确矛盾fail |
| 剩余问题 | 本路线没有解决什么，什么新证据会改变决定 |

机器可读模板见[最小示例](../../../examples/verification/revision-guidance.json)。文字任务单可使用本表，不必为低影响小改动生成全部记录。

## 本轮三个重要错例

### 历史作者做过，当前执行者仍未交付

Geneformer某条回复报告了分析；当前任务选择解释归一化因子的含义。历史分析报告归`historical_author`，当前解释归`current_work`。解释的completed必须指向本次文本；作者报告不能填到它的完成回执。若要验证数值稳定性，另选路线再索取相应输入。

### 解释已完成，未选OR分支不增加欠账

scANVI案例可用已取得的方法和图表解释标签及混合指标。数值验证分支缺少逐细胞ID和历史实现，因此细胞身份与未来供体泛化仍待补证；当前解释范围应限于已取得的材料。

### 将不同来源分别记录

PMDM案例把XML、补充PDF和评审PDF合在一项输入中，增加了接手者判断每项材料用途的难度。现在按文件分别记录来源；如果S15/S16是同一评审文件的两个段落，可共用来源并分别写定位和用途。已登记的验收项与实际执行回执分开记录。IC50或环统计只在对应问题触发时使用。

## 什么时候进入扩展

先选已有案例中具有真实来源的关键义务，按上述任务单交付并复核。当前范围能被一致说明、同类错误被稳定识别、合法替代路线能通过，再扩展新工作。若只修复了机器记录而领域方法仍需设计，继续补条件方法例；不把越来越多字段视作指导能力本身。
