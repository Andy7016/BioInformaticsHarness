# 功能与效用：从生物学目标设计最小验证

版本：`domain-validation-v1.1`，2026-10-18。针对ProtGPT2的功能/统计效用、DeepSEED的表达与诱导、GARNET的精选RNA构建体问题细化。下面的选路和设计步骤是本轮方法建议；作者实际做法见末尾来源。初版与本次修订依据保存在[公开研究设计与方法索引](../../../../docs/REFERENCES-AND-DESIGN.md)。

## 何时启用，先选择什么

当“预测得像、模拟稳定、分数更高”被用于支持功能、效用或机制时启用。先用一句话写：**哪个对象，在什么体系/条件下，应表现出什么可观察行为，结果将用于什么决定？** “生成蛋白有功能”缺少可共同检验的目标，先确定功能或改选效用问题。

| 目标与路线 | 为什么选它；必要输入 | 合法替代及保留范围 |
| --- | --- | --- |
| 指定体系中的直接功能 | 有与功能相连的测量，如给定条件下的表达、催化或翻译读出；需对象ID、对照、条件与重复结构。 | 可分析已有实验数据或交接新验证设计。换一个代理读出只能支持相应代理，不能自动替代功能。 |
| 外部任务上的计算效用 | 要判断模型能否帮助指定预测/排序/筛选；需外部目标标签、模型输出及开发/评价边界。 | 可用已保存且身份清楚的输出；比较系统效用不强制隔离所有机制。它不能证明模型生成的每个分子都有功能。 |
| 机制或因果贡献 | 问题是某段序列、表示、数据或条件是否造成变化；需能区分替代解释的干预/对照。 | 先做系统比较或关联分析并收窄归因；仅加一项相关性、跨体系结果或可视化不等价于机制验证。 |
| 解释、限域、保留局限 | 现有证据只有代理，或目标/输入尚不明确；原请求和已报告测量即可启动。 | 实际交付受限结论及改变它所需的证据；未选实验分支不增加欠账。 |

只选会回答当前问题的路线；没有功能/效用主张时不制造验证任务。当前项目可执行干实验、已有数据分析和验证设计交接；新湿实验另有执行环境与责任人。

## 拿到材料后的工作顺序

### 1. 先画测量链，确定可测目标

列“对象→实际读出→归一化/变换→目标构念→允许的句子”。对每个箭头问：它来自定义、已验证的校准关系，还是待检假设？例如物种最适生长温度不是单条RNA热稳定性；热处理后的翻译读出是该条件下的功能，不是普遍耐热机制。

选一个主要终点。表达项目同时关心高诱导输出与低基础表达时，分别保存两项及其比值；模型若只优化表达，不补写成已经优化“低泄漏”。需要多目标取舍时先写各目标优先级或可接受区域，保留相互冲突的结果。

### 2. 用对照排除最接近的替代解释

| 目标 | 优先比较 | 为什么需要；应匹配什么 |
| --- | --- | --- |
| 是否存在指定功能 | 已知阳性/野生型、阴性/背景与待测对象 | 先确认体系能看见该功能、背景可解释；匹配测量条件和归一化，区分无信号与测量失败。 |
| 算法是否提高实用命中/排序 | 当前可用基线和候选策略 | 匹配对象总体、评价终点、可用输入和筛选预算；保留所有被送测/预测对象、失败与排除。 |
| 某因素是否贡献提升 | 保持其他相关因素的匹配比较或明确的因子设计 | 架构、数据、初始化、编码、优化或筛选同时改变时，系统差异不能单独归给其中一个。先确定拟估计的效应，再选控制项。 |
| 能否迁移到新体系 | 按目标划分的蛋白、家族、供体、reporter或条件 | 留出轴来自未来用途；追溯预训练/开发/选模的暴露。新体系的观察不自动解释原体系的机制。 |

对照不够时，有两种具体动作：取得缺失对照再比较，或把问题改成现有设计能回答的描述。不要用另一种更容易的测量替换原目标。

### 3. 确定抽样对象和独立单位

- 列全候选→过滤→排名/专家选择→送测→有效结果的ID与数量；说明现在估计的是精选面板、某筛选策略的输出，还是原始候选总体。
- 同一构建体的多个技术孔不是多个构建体；同一蛋白的多个变异也不是多个独立蛋白。按实际制备、批次、母体/家族结构确定配对与分层。
- 要估计策略的命中率，按预声明策略获得全测或随机/分层抽样面板，保留选择概率与失败；只有精选成功例时，可报告这些对象的功能，不能外推全部候选。
- 不强制所有研究随机抽样。若目的就是验证指定的代表/极端构建体，给出选择理由，将结论限制在该选择范围。

### 4. 冻结读出、比较量和改判规则

记录单位、方向、背景扣除、检测/定量界限、失败规则、主要比较和聚合层级。背景扣除后非正的基础表达不宜直接作为fold-change分母；保留原值和可辨范围，不自动加pseudo-count。

对配对读出，先核逐单位`induced/basal`，再明确要估计`mean(induced)/mean(basal)`还是`mean(induced/basal)`。它们是不同事件。重采样和区间估计应服从独立单位/配对；重复层级未明时先给描述结果，停止总体精度结论。

把“足够”写成可改变行动的规则：

1. **功能存在/保持：** 对照与测量范围先有效，再以有生物意义的参考或功能界限判断。超过仪器背景只说明检测到信号，不自动等于达到应用要求。
2. **效用提升：** 事先从用途决定最小有意义效应`δ`和可接受不确定性；可参考实际筛选预算、容许错误及先导数据，记录理由。用先导数据规划精度/样本，不把先导与封存评价混用。
3. **采用区间的比较：** 若所选设计和估计方法适用，下界超过`δ`才支持相应提升；上界仍低于`δ`则撤回该幅度的提升主张；跨越`δ`时保持证据不足。非显著结果表示当前设计未分辨出差异；等效或非劣需要预先设定界限并采用相应设计。
4. **机制：** 先列能同样解释结果的最重要替代，再要求控制/干预能把它们区分。无法区分时保留关联或系统效用主张。

`δ`、区间方法、错误容许与样本量由具体用途决定；没有合理依据时先交付设计待决项，不套通用p值、固定三重复或统一功能阈值。

### 5. 分析与科学接受分开完成

先验收输入/测量有效性，再读取逐单位结果及对照，最后按预定规则写结论。控制失效意味着本次无法判断相应功能，不能直接判模型无效。测量正确但效应不足时应收窄或撤回具体主张；足够强的新证据也可以扩大范围，但要标明新的对象与条件。

最小产物可以合在一份`validation-plan.md`：目标句、选路理由、输入用途、对照/单位/终点、改判规则、缺失出口、执行与科学接受负责人。真正运行后再附逐单位结果和结论，不为填表虚构历史运行。

## 可以立即执行的小步与验收

配对表达算术例：

```powershell
python examples/domain-validation/expression_events.py --input examples/domain-validation/fixtures/expression-normal.json --output .scratch/domain-validation/expression.json
```

使用已具备的Python运行时。例子为明确标注的合成观测；其局部事件是比值/聚合审计，不评功能、统计显著性或测量的生物有效性。输入和输出细则见[例子说明](../../../examples/domain-validation/README.md)。

| 情形 | 采取的动作 |
| --- | --- |
| 正常：目标、对照、单位和事件相配，实际结果满足本路线规则 | 接受相应范围的分析与文字；科学结论交给指定研究者判断。 |
| 明确矛盾：MD当实测功能、精选4/6当总体命中率、9当成7.2所对应的事件 | 拒绝该句/该事件，保留原始结果，修正范围或运算。 |
| 缺材料：没有定义功能、对照失效、原始配对缺失、区间不足以分辨`δ` | 相应判断保持未知或不充分；解释路线仍可完成。 |
| 合法替代：选外部预测效用或准确的限域解释 | 按该路线自己的输入和产物验收，不索取未选实验的材料。 |

## 来源与推导

- **ProtGPT2**：该案例把序列生成、预测/模拟结果和功能请求分开；本指南据此先明确要判断的是指定体系中的功能、外部任务效用，还是有限范围的解释。[公开研究设计与方法索引](../../../../docs/REFERENCES-AND-DESIGN.md)
- **DeepSEED**：案例分别涉及诱导条件、表达比值和跨条件迁移。按路线保留各自的条件、单位和比较，才能知道每个读数回答什么问题。[公开研究设计与方法索引](../../../../docs/REFERENCES-AND-DESIGN.md)
- **GARNET**：专家挑选的 RNA 构建体需要保留选择过程、构建体、位点和反应单位。若讨论纯化或翻译读出，应查看论文方法中的对应步骤；补充材料中的突变图只提供背景。[公开研究设计与方法索引](../../../../docs/REFERENCES-AND-DESIGN.md)
- 本指南提出的对照、抽样和改判规则是可用于新研究的前瞻设计。逐项页码、原文阅读更正与旧归档定位见[机器记录](../../../../machine/document-notes/core/docs/methods/guides/function-and-utility-validation.md.json)。
