# 遇到指标冲突时，怎样做有限诊断

版本finite-diagnostics-v1，2026-10-19。触发条件是：同一对象的报告值与当前复算不同，或多个定义会改变结论。正常一致的结果无需为了符合流程再制造候选。本指南承接[指标语义卡](../cards/metric-semantics.md)、[测量到主张](measurement-to-claim.md)和[公开研究设计与方法索引](../../../../docs/REFERENCES-AND-DESIGN.md)。

## 1. 先确定比的是同一个事件

先核对象ID、源单元格、查询/参考、区域、方向、单位、聚合/分母与舍入。区分序列化文本差异、数值差异和数学事件差异。不移动行、不改原值，也不因某个新算法恰好吻合一行就替换原定义。

若已有数据经过不可逆归一化，先检查想问的量是否仍可确定。例如GARNET跨温度相对WT活动缺分母尺度，不能靠重复检验同一张表恢复自身保留率。材料不足时可继续报告同温度活动，并具体请求分母或原始测量。

## 2. 写下有来源依据的有限备选

每个候选说明数学事件、参考/窗口政策、归一化、适用单位和来源理由。先固定单位全集、组别、基准候选、容差、完整性与停止规则，再计算。异常后追加一个小来源排查时另立修订，写明已经看过什么。

DeepSEED实际35 bp由两段固定功能区和两个可变连续块组成。完整窗口ED、删除固定区后拼接ED、可变块各算ED后求和回答不同的对齐事件。拼接形成的接缝不是真实连续DNA。保留全长、按锚点比较或准确命名模板距离，都是随问题变化的合法路线；35/23/27和三个模板不是通用规定。

## 3. 对完整矩阵对账

固定units×candidates；明确失败、缺失和额外对象。不要从成功子集或最佳一行重写分母。可用[diagnostics工具](../research-support-tools.md)核矩阵并汇总：

| 结果 | 可以作出的判断 | 下一步 |
| --- | --- | --- |
| 一个共同候选与全部所评单位相容 | 当前面板没有排除这个定义。 | 核历史实现身份或再找能区分候选的材料；数值相符本身不识别过程。 |
| 多个候选向量完全相同 | 当前面板无法区分它们。 | 分开记录有证明的数学等价、来源声明的别名及经验同分；不当成多次独立确认。 |
| 不同单位各有不同候选相容 | 某些局部事件可解释该行。 | 仍核有无共同政策；不能按行拼成缺乏来源的历史算法。 |
| 某单位对全部预定候选均不相容 | 这个有限候选集没有解释它。 | 保存全部残差和源位置，索取能区分原因的历史中间产物。 |
| 必要单元缺失/失效 | 无法判断完整候选集或该单位。 | 补数据或保留unknown；不能称为全部候选均失败。 |

预先按源顺序选少量匹配/不匹配见证，可解释发生了什么；完整结果仍保留。涉及最优对齐时说明tie规则，一个显示路径不是唯一历史过程或真实演化轨迹。

## 4. 怎样停止，什么结果足以重开

候选集仍不能解释时，交付“哪些解释尚相容/被本面板排除、哪些不能区分、哪些源位置未解释”。写出原问题、缺失材料、负责提供与接收的角色、补后第一动作以及接受条件。工具不自动判断作者错误，也不搜索算法或分母直到吻合。

能回到残差单元格的历史脚本、实际切片/掩膜、query/reference/output索引和导出/舍入账本，是DeepSEED下一动作。新材料支持一个历史共同政策或显示原映射确有错误，才另立修订改变相应判断。当前96×17中22条基准残差、14条全候选未解释是该实例的结果。

~~~mermaid
flowchart TD
    A["发现报告值与复算不同"] --> B["核对象、事件、尺度和表示"]
    B --> C["固定有限候选与完整单位"]
    C --> D["对账与固定见证"]
    D --> E["共同相容、局部相容、不可区分或未解释"]
    E --> F["交付有限判断和具体材料任务"]
    F --> G["新材料能区分解释时另立修订"]
~~~

所用数值容差和有用性阈值分别由数据精度及研究用途决定。工具对已提供矩阵做算术/完整性整理，科学选择和结论由研究负责人验收。
