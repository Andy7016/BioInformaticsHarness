# 从证据缺口到下一步研究

## 先判断缺口是否值得处理

写出当前结论、希望回答的新问题，以及缺失信息怎样影响两者。例如，短序列相似度和名称可用于构建代理分组；若要声称跨基因泛化，就需要相应的生物学实体关系。

比较补资源与几种替代：保留原问题、缩小问题、换一个能回答同一问题的来源，或停止当前分支。选择获取路线时，明确预算和什么观察会使它值得继续。

## 获取后按用途核查

保留实际来源、资源版本和获取结果。核查当前用途需要的字段、实体类型、覆盖、歧义和冲突；已有材料没有给出的关系保持未知。

名称、序列簇、基因和家族是不同对象。不要只改字段名称就升级评价单位。多个候选映射可以并存，合并或排除需要说明理由。

覆盖要求随用途选择。只有部分样本得到可靠映射时，说明哪些样本被保留；比较划分方法时，尽量在共同样本上区分分组影响与样本改变的影响。

## 实际消费资源

将资源连到具体步骤：它是用于数据选择、训练、划分、评价真值，还是事后解释？先明确这些用途，再执行相应程序。资源文件存在和字段齐全，只完成了接收的一部分。

模型结果比较要保存实际使用的关系、评价记录和输出。准备任务也可以消费官方资料，判断它能否建立目标评价单位；此时产物是准备结论，后续模型计算按该结论选择路线。

## 用结果关闭这一轮

把资源核查和实际消费结果与原判据对照，给出保留、修改、收窄、暂缓或停止的理由。新方案另存版本，旧结论和此前信息继续保留。

因证据不足而修改后续方案时，说明受影响的要求、改变理由和下一个验证点。当前未解决的资格问题继续保留；新的执行按相应预算和方案启动。

如果资源充分，就选择下一项计算；如果资源仍不足，说明哪个目标暂时无法回答，并留下恢复该分支所需的材料。取得较弱证据时，也可以接受一个明确限域的成果。

本流程由研究调控层选择，有界任务完成获取和消费。[任务连续性指南](task-continuity.md)帮助多轮工作保持当前入口；精确字段和程序接口见[机器设计](../../../machine/design/resource-gap-loop.json)。
