# D51：恢复当前任务，验收本轮交付

## 问题

同一课题往往保留原方案、首次交付和新的补分析。入口文件各自正确，也可能在会话恢复后拿错一轮材料：研究者转回旧目录，核验了已经接受的成果，却没有完成当前问题。

一次后续研究出现了这种情况。研究者先在新子目录接收方案并准备代码，会话压缩后回到原研究目录，最后交付旧成果的复核。原方案和成果没有损坏；缺少的是恢复时对当前任务的重新确认，以及交付时对本轮义务的检查。

## 决定

在需要续跑、搬迁或同时保留多轮研究的任务中，把研究、轮次、任务目标、所选工作阶段、权威入口、工作位置和下一验收点放在同一份任务上下文中。它保存这次任务的约定，实际进度由本轮产物与回执接续。范围、方案或生效授权改变时形成新版本，旧版本继续保留。

运行器在启动实际计算前读取这份上下文；交付检查也读取同一份上下文。新一轮交付必须满足本轮选定的产物要求，并将所要求的真实运行连到这一轮任务。旧研究仍可作为输入和比较依据。

这项设计补充 [D47 的唯一交接入口](24-production-consumption-and-handoff.md)和 [D50 的计划封存](27-sealing-capture-and-public-checkpoint.md)。原有封存格式继续使用；任务上下文单独维护，不向首次方案的旧清单追加字段。

## 取舍

只给会话一段提醒容易遗失当前轮次；强制每项小操作都建立完整工作流又会增加负担。这里选择可选的任务上下文接口：简单的一次性任务可继续使用原入口，跨阶段和多轮任务使用明确绑定。

已有调度平台能提供同等的任务身份、恢复位置、运行关联和交付判定时，可以使用该平台的记录。科学验收仍由研究者和评阅者判断，工具负责核对本轮约定及其文件关系。

## 应用与验收

先用小型真实子进程检验正确任务可以执行，错误轮次、旧目录和旧交付会停止在启动或交付检查之前。再在 Splice 的资源准备中实际使用这套接口。当前 Yeast 沿用原冻结输入继续研究，父方提供的恢复支持另行记录。

使用方法见[任务连续性指南](../methods/guides/task-continuity.md)。精确接口、测试与适用范围见[机器记录](../../machine/design/task-continuity.json)。
