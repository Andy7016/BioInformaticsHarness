# 同行评审与修订：新的外部参照

日期：2026-10-15。来源：用户要求在后续案例分析中额外统计同行评审观点与 Harness 的重合度，并提出早期稿件可能是必要输入。承接[具体义务与实际使用 D30–D32](15-obligations-guidance-and-prospective-use.md)。

## D33：以具体 concern 和稿件版本对照

研究指导应能接续到审阅与修订：审阅者识别问题，作者或修订agent理解依据并选择回应，再由新证据和新版本接受复核。本轮沿用 Review、Decision、Task、Run/Artifact、Claim 和后续 Review 连接这些步骤。

统计单位是“去重后的具体 concern × 被评稿件版本”。拆开复合意见，保留多位评审对同一问题的来源；同一问题在回信和后续轮次中重复出现时，通过父子关系保留演变，避免靠段落数放大权重。

对每条 concern 分别记录：

- 评审原意、来源位置、当时可见的稿件/补充/代码版本。
- 当时已冻结的 Harness 是否能表达该义务、是否有可操作指导、哪些谓词已有检查。
- 作者如何回应：认可并修改、部分处理、提供反证、合理保留，或仍有分歧。
- 实际新增了什么产物或主张修订，后续复核依据是什么。

E/G/V 与作者是否采纳分别登记。需要科学判断的问题可以由具名 agent 或人提出意见，真实人的接受继续单列。

## 同一主题与可用指导分开

两份材料都提到“泛化”“泄漏”“可解释性”只说明主题接近。可操作的重合应落实到同一触发、对象、证据和选择：例如哪些对象必须分开，哪份标签不能回流到选择，哪项结果需要限制外推，以及作者可以怎样补证或调整主张。

正向统计覆盖同行评审提出的适用问题；反向记录 Harness 的适用义务中哪些没有被评审提及。两边都公开分母、未知和排除原因。评审未提及某义务，只能支持“本轮未提及”的观察；评审关注点的必要性则结合作者依据与修订结果判断。

## 早期版本决定能回答多强的问题

精确送审稿及其配套材料最有价值。带日期的预印本可以作为早期代理版本，须登记与送审稿的对应依据；只有终稿时仍可整理评审主题与框架的关系。

若希望观察 Harness 能否提前帮助审阅，后续试点按两阶段展开：先给新agent早期材料和冻结的 Harness，保存其问题、理由与建议；再开放公开评审和作者回应作对照。已读过评审或终稿的情况照实登记。精确版本无法取得时，缩小到材料所支持的比较。

## 如何协助修订者

每条拟处理意见形成一条明确链：

`concern及版本 → 对问题的理解与双方依据 → Decision及替代 → 有界修订任务 → 新产物/主张 → 对照原意见复核`

补实验、补分析、修正文稿、收窄主张和有依据地反驳均可成为合理路线；具体选择由研究证据决定。回信是否解释了问题、代码是否执行成功、结论是否得到支持分别检查。保留未采纳的理由和仍未解决的分歧，有助于继续研究。
