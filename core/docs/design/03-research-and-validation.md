# 研究与验证计划

状态：建议方案，未启动模型实验、完整工作流复现或用户研究。需求链见 [设计图景](01-design-vision.md)，争议见 [登记](../ARCHIVE_POINTERS.md#archive-pointer-aff2be8d1573d125)。

## 1. 先回答可以被推翻的问题

- **R1 方法有效性**：在相同模型、可见资料范围和匹配资源下，方法卡与可执行检查是否减少严重方法错误？
- **R2 验证可靠性**：检查器能否识别形式正确但科学错误的解，同时接纳有效替代分析和恰当报告不足的解？
- **R3 可接手性**：独立研究者能否仅凭研究包重建关键结果，定位缺失假设及失败？
- **R4 学习迁移**：撤去辅助后，使用者能否在新数据/问题上更好地解释方法选择、识别泄漏和混杂？

负面结果同样有价值：方法卡只改善报告格式、严重错误不减、检查器误伤上升，或辅助表现提高而迁移不变，都应导致缩减或修改设计。

## 2. 最小任务包的候选验收

| 候选 | 正常任务 | 扰动/反例 | 不应误判 |
|---|---|---|---|
| 单细胞条件差异分析 | 有供体、条件、批次元数据，回答明确细胞类型下的问题 | 供体信息缺失；条件与批次完全混杂；把细胞当独立生物学重复 | 有依据且尊重设计的替代模型；准确限定不可识别的条件效应，但保留合法描述性分析 |
| RNA 下游预测 | 明确目标泛化对象，训练/验证/测试和标签来源可追踪 | 相似性跨划分；全体数据拟合预处理；使用测试集选超参数 | 与目标泛化场景相匹配的划分；如实声明预训练重叠未知 |

表中是方法风险驱动的候选设计，不是对任一具体数据集已经可用的声明。pseudobulk、同源性分组都不是无条件唯一正确答案。固定表征训练预测头、微调和从零训练分别标注；不得混报能力范围。

## 3. 底座选型实验（待开展）

用同一份最小输入/输出契约，先做成本较低的手工或脚本化执行：

1. 准备一个只读小输入、一个可写成果目录及外置验证器；不依赖收费模型完成环境检查。
2. 比较 Inspect/Harbor 对当前计算环境的支持、工具事件完整性、失败状态、资源限制和恢复方式。
3. 在全新环境重跑成果；检查是否意外依赖原执行目录、缓存或未记录文件。
4. 验证被测执行者确实无法读取或改写参考答案；测试证据必须是权限/挂载结果。
5. 对 Snakemake/Nextflow 只在任务确有依赖编排需要时接入，记录集成成本。

选择标准：达到必要边界、维护成本可承担且可复查。仓库 README 的宣称仅作为候选筛选依据。

## 4. 验证器先校准，再评系统

建立由独立审阅者判断的少量对照成果：正确参考解、合理替代解、方法错误但文件正确的解、未运行却声称成功的解、准确报告信息不足的解。

记录各类接受/拒绝、误判原因和分歧；样本不足时直接报告计数而不是夸大率估计。确定性程序负责可靠形式化的检查；专家负责解释与方法争议；LLM judge 的版本和提示固定，输出作为辅助裁决依据并保留复核。

检查器不能使用被测系统自述作为实际运行的唯一证据，也不能只检查报告是否包含“泄漏”“批次”等词。隐藏评分材料是任务级结果和裁决，不应把应公开的方法规范全都隐藏。

## 5. 试点对照与统计边界

候选条件：C0 同工具的普通执行环境；C1 加方法文档；C2 加可执行检查与证据要求。先确认这些干预没有改变任务答案可见性。分别记录模型调用、时间、费用、CPU/GPU、人工干预和失败；预算匹配可采用上限与资源曲线，不能只比较 token 数。

按研究/数据来源分组，变体与重复运行不当作独立论文级样本。试点估计方差、失败机制和成本后再确定样本量，不把 A1 的216次运行示例当作功效分析。模型×harness 的小型交叉研究可以识别交互，但任务太少时不能推广到整个生信领域。

分别报告执行、方法、证据、稳健性与资源；重大泄漏和虚构结果明确标记，不被文风分数抵消。受控模型实验与各自原生系统实验分表。
