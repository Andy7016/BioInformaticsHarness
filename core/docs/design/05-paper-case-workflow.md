# 以已发表论文检验研究流程与 Harness

日期：2026-09-26。依据：[用户确认](../ARCHIVE_POINTERS.md#archive-pointer-5143f2f13d216007)、[已确认设计与追溯矩阵](../ARCHIVE_POINTERS.md#archive-pointer-fcaa0af8ba402b33)。本文是下一阶段的工作方案，不是已完成的案例研究。

## 1. 目标与工作顺序

通过真实论文回答：harness 能否表达和支持研究中必要的判断、操作、证据与修订？先建立研究流程参考，再让实际案例约束底座和接口选择。

建议顺序：候选论文小范围比较 → 一篇论文的完整研究逻辑 → 一个主要结论的计算证据链 → 小规模重跑/独立检查 → 缺口与成本分析 → 底座及部署决策。

**论文是观察对象，不能直接当规范答案。** 区分作者做了什么、作者为何这样做、本次能验证什么、我们建议怎样做。可重现原结果与支持原主张分别判断；合理替代路径应被保留。

## 2. 两张相连但不同的图

- **科学论证图**：研究问题 → 目标总体/估计目标 → 比较与对照 → 数据证据 → 主张 → 替代解释及局限。
- **计算依赖图**：数据版本 → 处理/拟合/划分 → 分析或模型 → 表格/统计量/图形 → 对应主张。

跨两图标出决策点：纳入排除、质控、分析单位、协变量、特征与模型选择、多重比较、稳健性分析、停止或修订。脚本依赖顺序不能自动解释这些决定。

论文往往是整理后的叙述，不记录实际探索顺序、失败分支和所有调参。由正文、补充资料、代码重建的流程应称为“可恢复的流程”；缺失历史标 unknown，不编造作者当时的理由。后续自己执行时再记录真实决策过程。

## 3. 首例选择：优先可解释的完整证据链

建议先比较 2–3 篇候选，只选择一篇进入详细拆解。选择维度如下，不宜先压成单一总分：

| 维度 | 希望看到的条件 | 需要记录的缺口 |
|---|---|---|
| 科学问题 | 主要结论清楚，分析单位、对照和外推范围可辨 | 结论过宽、只有任务分数而缺研究问题 |
| 资料可恢复性 | 全文、方法/补充、数据标识、代码及版本线索 | 元数据缺失、关键步骤只在交互操作中存在 |
| 计算边界 | 一条主要结论可在可接受资源内重跑 | 必须重建全部原始数据流程才能开始 |
| 方法判断 | 有少量有意义的选择及诊断，可讨论替代 | 完全机械转换，或过多未知决定混在一起 |
| 验收证据 | 可以独立检查关键数值、单位、方向及稳健性 | 只靠图像相似或作者答案判定 |
| 使用与公开 | 能查清文章、代码、数据各自的使用条件 | 可下载但再分发条件尚不清楚 |

第一例只需覆盖若干关键矩阵项，例如 D01/D02/D04/D07/D10；不必为了覆盖 D01–D14 而选择庞大混合课题。记录“不适用”本身也是框架检验。

用户同轮已选择：**优先生物模型训练与泛化评估案例**。首例按此筛选，仍不将模型训练流程宣称为所有生信研究的唯一流程。方法学论文可为案例中的判断提供依据，不必同时作为首个被完整复现的案例。

### 模型案例的重点

优先寻找一个明确预测任务、可恢复训练过程和有解释空间的泛化主张。首例最好能承担至少一次完整训练或明确标识的微调；只调用现成模型推理不足以覆盖训练阶段，但若基础模型预训练不可重现，应把预训练来源作为外部依赖和证据缺口，而非声称已复现全模型。

拆解顺序建议为：

`生物学问题与目标总体 → 数据/标签与依赖结构 → 泛化目标及划分 → 预处理拟合 → 基线与模型训练 → 验证集调参/选择 → 冻结测试 → 分组误差与稳健性 → 科学主张`

其中需要特别追问：

- “新样本”具体指什么：已知对象的新测量、新供体/中心/时间、新序列家族或新分子类别？由论文目标决定需要哪种外推，不默认越远越好。
- 标签如何形成，重复、同源、同批或共享实体怎样连接？矩阵行数是否代表独立样本？
- 预处理、特征筛选、预训练表征及调参各看过哪些数据？未知训练来源保持未知。
- 参考模型与简单基线是否用一致的数据、信息和选择预算？最终测试是否在选择后才使用？
- 不确定性分别来自训练种子、数据划分还是独立实体？不能把重复训练次数当生物样本数。

优先矩阵项为 D01–D05、D07、D09–D12；D03 的具体相似度策略取决于任务，不预设必须使用 DataSAIL。可考虑用“同一预测目标下的合理替代模型”和“全量数据拟合预处理等受控错误”检验框架；替代划分若改变泛化目标，应单列为另一研究问题，不能混作公平排名。

## 4. 拆解表：直接连接原文与可检查对象

每个步骤至少记录：

| 字段 | 内容 |
|---|---|
| 来源 | 正文章节/图表、补充、代码路径与版本；来源间不一致保留双方 |
| 意图与理由 | 该步回答哪个问题；理由为作者明示、代码推断或本次建议 |
| 输入与输出 | 版本、样本身份、表示状态、单位、关键产物 |
| 方法前提 | 分析单位、依赖关系、适用假设、信息访问与拟合范围 |
| 决策与替代 | 参数、诊断、允许替代路径；历史无法恢复则注明 |
| 验收 | 可确定性检查的内容、需重算的内容、需人判断的内容 |
| 框架映射 | 对应契约和 D 编号；原生表达、需适配、缺失、不适用 |
| 实际成本 | 环境准备、运行、存储、模型调用、人工检查分别记录 |

建议交付：案例说明、论证图、计算依赖图、步骤表、资料/缺口清单、harness 适配记录。执行阶段再增加运行清单、结果差异和失败记录。

## 5. 如何检验“契合”而不是将案例强塞进框架

先按论文自身逻辑拆解，再映射框架。若关键研究决定只能埋进自由文本、产物缺少必要身份、合理分支被流程拒绝，应记为框架缺口，而非责怪论文不合模板。

第一轮围绕一个主要结论保留三条路径：

1. 原文可恢复的参考路径：确认其资料、输入、过程与结果对应关系。
2. 一条合理替代路径：检查框架能否容纳不同但有依据的分析，并表达差异。
3. 一个受控错误对照：例如分析单位错用或样本标签错配，检查是否出现可解释的失效信号。

这三条路径是本项目后续验证设计，不是假称作者做过的实验。降低数据规模时明确改变了什么；小样本冒烟运行仅验证工程链条，不能声称复现全量科学结论。

评价框架是否有用，至少观察：能否追问主张到输入和决定、能否发现预设错误、是否误伤替代方案、中断后能否接续，以及额外记录/审阅负担。暂不以“所有字段填写完成”作为成功标准。

## 6. 五项待决事项怎样被案例约束

| 待决事项 | 现在可做 | 案例拆解/试跑后决定 |
|---|---|---|
| 底座 | 定义需要采集的事件、产物及独立验证边界 | 用同一小案例比较候选适配成本、恢复与证据覆盖 |
| 首个数据集 | 识别论文所用数据、必要元数据及关键分析切片 | 全量或可解释子集；从原始读段还是处理矩阵进入 |
| 执行预算 | 将资料恢复、冒烟、参考重跑、替代与错误对照分阶段 | 按实际资源估计给每阶段上限；模型费之外计入存储及人时 |
| 公开许可 | 分开登记自有代码/文档、第三方代码、论文和数据的条件 | 决定哪些内容可打包，哪些仅提供获取脚本/定位；再定自有产物许可 |
| 部署环境 | 收集 OS、R/Python/工具、CPU/GPU/RAM、联网及数据约束 | 决定 Windows 上编排配合何种计算环境，或服务器/HPC 是否必要 |

这些事项不完全后置：明显的访问、资源和平台障碍应在筛选时发现。尚未获得机器资源信息或案例测量前，不凭感觉承诺金额、时长和全量可运行性。
