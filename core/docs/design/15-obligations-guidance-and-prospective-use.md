## D30：比较具体义务，保留原来的评价

一个研究问题可以同时包含两项不同的工作：判断问题是否有科学价值，以及把问题、主张、证据和版本连起来。前者需要研究判断，后者可以有明确的记录检查。同样，重要决定的理由、说明的可读性和研究者的接受，不取消其修订关系、来源锚点和审阅对象版本的检查义务。

本轮采用“适用条件 → 原子义务 → 最少证据 → 判据 → 实现与执行 → 剩余人工判断”的比较单位。义务标识保持稳定；其所属 R 和区域只是导航。同一谓词由另一个义务或接口承担时，链接到实际承担处，避免重复计数。

分别保存三件事：

1. 原案例如何切分、如何评分；
2. 在共同义务范围内，本次校准如何判断、依据是什么；
3. 后续指导或实现新增了什么，何时再检查其效果。

先为最新五例的全部原义务建立来源索引，重点校准 R01、R19、R20、R21 的五例共同范围。其它义务保持原判。这个范围解决已定位的粒度差异；后续按同一规则扩展，不重新解释旧案例来制造趋势。

入口：[具体义务校准](../ARCHIVE_POINTERS.md#archive-pointer-650ae92eab1067f3)。

## D31：两组指导要回答实际选择

第一组是[统计单位与选择后的评价](../methods/guides/statistical-units-and-selection.md)：研究者怎样判断什么算一次观测、什么算独立重复，怎样在多候选、轨迹、fold、供体和选择后子集中定义要估计的量，以及怎样挑选适合的比较和不确定性方法。

第二组是[信息与状态的作用](../methods/guides/information-and-state-effects.md)：数据、标签、先验、选择分数、mask和内部统计状态在哪一步起作用，哪些作用与当前主张相容，怎样保存足以接续研究的版本与实际使用证据。

每组都提供触发问题、输入、可选方案及取舍、输出模板、例子和完成检查。先帮助执行者作选择，再回到已有对象保存决定。具体算法仍由适用的方法或外部实现定义；不增加顶层对象，不给所有研究指定同一种重采样、划分或独立测试方案。

## D32：用受限材料观察研究怎样展开

下一份使用样例选择能在本机 CPU 上推进的经典序列模型工作。父任务保存完整论文、补充、实现与流程参照；新建 GPT-6.1-Sol / xhigh 会话只收到早期科学动机、问题、明确身份的数据、预算及精简的 Harness 指导。研究者可以选择合理的不同方法；验收重点是其选择与证据如何回答问题。

执行分阶段留痕：先保存研究方案与理由，再做小规模真实实验，保存实际输入、拟合调用、预测、失败与资源记录，最后形成便于人阅读的解释。原论文的方法与结果在提交冻结后开放，分别比较问题、方法取舍、执行链和结论。

本轮定位为**受限材料的方法再实现与研究指导使用样例**。原样重跑需要原代码与配置；数值复现需要相匹配的数据、方法和规模。它们可在揭示参照后作为后续步骤。

新会话使用单独输入目录，不继承本对话；允许目录和来源访问写入任务约定。当前是协作中的材料限制，不是操作系统强制隔离的 benchmark。自动注入的记忆、既有知识识别、额外读取和人工提示均由会话登记，用于解释它实际接受了多少帮助。

启动前固定输入清单、预算、检查范围及父任务的比较问题。方法选择自由，计划改变须说明观察与理由；对账、输入身份和来源忠实性按记录检查，科学意义由审阅解释。首轮用于发现指南中的阻力；若之后要估计 Harness 的增益，再设计匹配预算和输入条件的对照试验。

入口：[CPU 使用样例](../ARCHIVE_POINTERS.md#archive-pointer-f97713a77ee20e83)。
